# Mini NPU Simulator

AI 칩(NPU)의 핵심 연산인 MAC(Multiply-Accumulate)을 파이썬으로 직접 구현해,
십자가(Cross)와 X 패턴을 판별하는 콘솔 프로그램입니다. 외부 라이브러리 없이
표준 라이브러리(json, math, time)만 사용했습니다.

## 실행 방법

```
python3 main.py
```

- 모드 1: 사용자 입력 (3x3) - 필터 A, B와 패턴을 한 줄씩(공백 구분) 입력
- 모드 2: data.json 분석 - `main.py`와 같은 폴더의 `data.json`을 읽어 일괄 판정

`make_data.py`는 모드 2 검증용 테스트 `data.json`을 만드는 보조 스크립트입니다.
(`python3 make_data.py`)

## 구현 요약

- **MAC 연산**: `mac(pattern, filt)`가 이중 for문으로 같은 위치 값끼리 곱해 모두 더합니다. NumPy 등은 쓰지 않았습니다.
- **라벨 정규화**: `normalize_label()`이 expected 값(`+`, `x`)과 필터 키(`cross`, `x`)를 표준 라벨 `Cross`, `X`로 통일합니다. 대소문자와 공백은 무시하고, 알 수 없는 표기는 오류로 처리합니다. 출력과 PASS/FAIL 비교는 모두 표준 라벨 기준입니다.
- **동점 처리(epsilon)**: `judge()`는 두 점수의 차이가 `1e-9` 미만이면 동점으로 보고 `UNDECIDED`를 반환합니다. 동점이 아니면 점수가 높은 쪽이 판정입니다. `UNDECIDED`는 expected와 다르므로 FAIL로 집계합니다.
- **입력 검증(모드 1)**: 줄의 숫자 개수 불일치, 숫자가 아닌 값을 걸러 안내 문구를 출력하고 재입력을 받습니다.
- **스키마/크기 검증(모드 2)**: 패턴 키 `size_N_idx`에서 N을 추출해 `size_N` 필터를 고르고, 패턴이 N×N이 아니면 FAIL 처리합니다. 케이스마다 예외를 잡아서 한 건이 실패해도 프로그램이 멈추지 않습니다.
- **시간 측정**: `time.perf_counter()`로 `mac()` 호출 구간만 재고, 크기별로 10회 반복한 평균(ms)을 냅니다. 파일 읽기와 출력 시간은 제외합니다.

## 결과 리포트

### 1. 실행 결과 요약

모드 2(`data.json` 분석)를 테스트 데이터로 실행한 결과 총 10건 중 6건 통과, 4건 실패입니다.
실패 4건은 프로그램 결함이 아니라, 오류 처리를 확인하려고 일부러 넣은 케이스입니다.

### 2. FAIL 원인 분석

| 케이스 | 실패 사유 | 원인 분류 |
|---|---|---|
| size_5_3 | 모든 칸이 0인 패턴이라 두 점수가 0.0으로 같아 UNDECIDED | 수치 비교 문제 (동점 정책) |
| size_13_3 | 13×13 필터에 5×5 패턴이 들어와 크기 불일치 | 데이터/스키마 문제 |
| size_5_4 | expected가 `circle`이라 표준 라벨로 정규화할 수 없음 | 데이터/스키마 문제 (라벨) |
| size_7_1 | `size_7` 필터가 data.json에 없음 | 데이터/스키마 문제 |

- 4건 중 3건은 데이터 쪽 문제이고, 판정 로직이 틀려서 실패한 케이스는 없습니다.
- size_5_3은 점수가 같으면 어느 쪽도 고를 수 없다는 정책에 따라 FAIL이 된 것입니다. 이 데이터의 동점은 실제로 값이 같은 경우입니다.
- 값이 0과 1뿐인 정수 데이터는 부동소수점 오차가 거의 없습니다. 그러나 소수가 섞이면 `0.1 + 0.2 == 0.3`이 `False`가 되는 것처럼 같아야 할 값이 미세하게 달라질 수 있습니다. 그래서 `==` 대신 `abs(a - b) < 1e-9`로 비교합니다.
- 정규화가 없었다면 expected `+`와 필터 키 `cross`가 서로 다른 문자열이라 정상 케이스도 FAIL이 됐을 것입니다. 정규화로 표기 차이에서 오는 가짜 실패를 막았습니다.
- 크기 검증과 케이스 단위 예외 처리 덕분에 오류 데이터가 섞여 있어도 나머지 케이스는 끝까지 판정됩니다.
- (실패가 0건인 데이터로 실행하면, 정규화와 epsilon 비교가 표기와 오차 때문에 생길 수 있는 오판을 막았기 때문입니다.)

### 3. 성능 분석 (평균/10회)

| 크기 | 평균 시간(ms) | 연산 횟수(N²) |
|---|---|---|
| 3×3 | 0.0006 | 9 |
| 5×5 | 0.0017 | 25 |
| 13×13 | 0.0106 | 169 |
| 25×25 | 0.0388 | 625 |

- 5×5에서 25×25로 가면 연산 횟수는 25배(25 → 625)이고, 측정 시간은 약 22.8배(0.0017 → 0.0388ms) 늘었습니다.
- 3×3에서 13×13으로 가면 연산 횟수는 약 18.8배(9 → 169), 시간은 약 17.7배 늘었습니다.
- 연산 횟수와 시간이 비슷한 비율로 늘어나므로, 시간은 한 변의 길이 N에 비례하는 것이 아니라 N²에 비례합니다.
- 이유는 `mac()`의 구조입니다. 바깥 for문이 N번, 안쪽 for문이 N번 돌아 총 N × N번 곱셈과 덧셈을 합니다. 따라서 시간 복잡도는 **O(N²)** 입니다.
- 3×3처럼 아주 짧은 시간은 측정 오차가 커서 실행할 때마다 값이 흔들립니다. 그래서 10회 반복 평균을 내고, 본 측정 전에 워밍업을 1회 실행했습니다.
- 실제 NPU는 이 N²번의 곱셈을 병렬로 동시에 처리해서 시간을 줄입니다. 이 프로그램은 CPU에서 순서대로 계산하므로 N²이 그대로 시간으로 드러납니다.# Mini NPU Simulator
